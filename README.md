# Phap Dien AI — LegalGraphRAG for Vietnamese Labor Law

Repository: [tvqui/phap-dien-ai-legalgraphrag](https://github.com/tvqui/phap-dien-ai-legalgraphrag)

This project includes an **OFFLINE** data-building and validation pipeline, an **ONLINE** backend for retrieving legal sources and generating answers, a web interface, and evaluation suites. The backend reads prebuilt artifacts; it does not search the web for new laws for each question.

## Choose the Right Workflow

| Goal | Guide | Output |
|---|---|---|
| Run the API and web interface locally | [Run ONLINE locally](#run-online-locally-on-windows) | API at http://127.0.0.1:8000; web interface at http://127.0.0.1:5173 |
| Run the backend on Kaggle | [Run the ONLINE backend on Kaggle](#run-the-online-backend-on-kaggle) | Temporary backend URL and logs |
| Build data from scratch | [OFFLINE pipeline](docs/offline.md), [artifact packaging](docs/offline/artifact-layout.md) | `vn_labor_online.zip` and a review package |
| Use the prebuilt output | `sample_data/vn_labor_online.zip` | Run the backend without rebuilding OFFLINE |
| Submission/sample run | [OFFLINE Kaggle notebook](build/submission/offline/VN_Labor_Kaggle_V8.ipynb), [sample ONLINE input ZIP](build/submission/online/sample_input/vn_labor_online.zip) | Both handoff files are available after cloning |
| Evaluate quality | [evaluation/README.md](evaluation/README.md) | Results for each evaluation |

## Repository Structure

~~~text
src/
  offline/src/vn_labor_offline/       Build, normalize, and validate data
  offline/config, scripts, kaggle, tests
  online/backend/src/vn_labor_online/ API, retrieval, verification, answer generation
  online/backend/config, scripts, kaggle, tests
  online/frontend/                    React/Vite web interface
evaluation/                           Gold data, evaluation protocols and code, Kaggle notebooks
data/                                 Data instructions; large datasets are not committed
docs/                                 Architecture and guides
~~~

PDF/DOCX corpora, intermediate build caches, model weights, and API keys are not stored in Git. The repository includes a prebuilt ONLINE artifact at `sample_data/vn_labor_online.zip` for quick use; the two handoff files in `build/submission/` are explicit exceptions tracked by Git. Other outputs under `build/` remain ignored. Do not commit `.env`, tokens, or API keys.

**After cloning:** Create `build/releases/vn_labor_online.zip` by copying the sample ZIP above; `build/online_pinned.yaml` is generated by the artifact-pinning command. `build/kaggle/` is created only after running `run.bat kaggle` and requires an input corpus. The `data/`, `review/attachments/`, and `artifacts/` directories are not included in Git: provide the configured source files yourself, then run the pipeline to create artifacts. `.env` is not cloned either; use `.env.example` as a template if you need to configure secrets.

## Run ONLINE Locally on Windows

### Requirements

- Windows 10/11, Git, Python **3.12 or 3.13**, and a Node.js LTS version supported by Vite.
- A validated OFFLINE artifact, usually `vn_labor_online.zip`.
- Internet access for the initial dependency installation and model downloads. A GPU is optional but can speed up Dense retrieval.
- Ollama and Docker/Neo4j are needed only if required by your selected configuration; they are not required for the default steps below.

### 1. Clone the Repository and Set Up the Environment

Open PowerShell:

~~~powershell
git clone https://github.com/tvqui/phap-dien-ai-legalgraphrag.git
Set-Location -LiteralPath ./phap-dien-ai-legalgraphrag
run.bat setup-full
~~~

If you already have the repository locally, open PowerShell at its root and run `run.bat setup-full`.

### 2. Place the Artifact

Create the directory, then copy **`vn_labor_online.zip`** into it:

~~~powershell
New-Item -ItemType Directory -Force build/releases | Out-Null
~~~

The expected path is `build/releases/vn_labor_online.zip`. The repository includes a prebuilt OFFLINE artifact at `sample_data/vn_labor_online.zip`; to test or demo without rerunning OFFLINE, use:

~~~powershell
Copy-Item -LiteralPath sample_data/vn_labor_online.zip -Destination build/releases/vn_labor_online.zip -Force
~~~

If your team has a newer ZIP, you can use it instead of the sample. Do not use `vn_labor_offline_review.zip`, a Gold ZIP, a checkpoint, or a research directory as the runtime artifact.

### 3. Pin the Correct Artifact in the Configuration

Run from the repository root:

~~~powershell
./.venv/Scripts/python.exe -B -X utf8 src/online/backend/scripts/pin_online_artifact.py --artifact build/releases/vn_labor_online.zip --base-config src/online/backend/config/online.yaml --output build/online_pinned.yaml
~~~

This command checks technical compatibility and writes fingerprints to `build/online_pinned.yaml`; it does not approve the legal content. Rerun it whenever the artifact changes. Do not reuse stale fingerprints or bypass the checks.

If your local `.env` defines `VN_LABOR_ARTIFACT_SOURCE`, make sure it points to the same ZIP:

~~~dotenv
VN_LABOR_ARTIFACT_SOURCE=build/releases/vn_labor_online.zip
~~~

### 4. Check and Run the API

~~~powershell
run.bat online-check -Config build/online_pinned.yaml
run.bat online -Config build/online_pinned.yaml
~~~

Keep the PowerShell window open. The API is at http://127.0.0.1:8000, with API documentation at http://127.0.0.1:8000/docs. Check `/health` and `/ready` for service status.

The sample configuration uses deterministic behavior for some roles. `GEMINI_API_KEY` is required only if Gemini is enabled; if Ollama is enabled, start Ollama and download the configured model. Using Gemini over the Internet does not mean the system searches the web for new laws.

### 5. Run the Web Interface

Open a **second PowerShell window** at the repository root:

~~~powershell
run.bat frontend
~~~

Open http://127.0.0.1:5173. Stop each process by pressing Ctrl+C in its corresponding window.

Run local checks with `run.bat help`, `run.bat test`, or `run.bat validate`. Tests use fixtures/mocks for steps requiring external services; passing tests do not replace legal review.

## Build OFFLINE Data Locally on Windows

This workflow builds from PDF/HTML/DOCX corpora available on your machine. Source data is not stored in Git; provide the complete corpus required by the project catalog.

### 1. Prepare the Sources

Place the source files under `data/` according to the default configuration:

~~~text
data/
  legal_corpus/       Labor laws and related legal documents
  judicial_corpus/    Judgments/case law, if included in the approved source set
  supplementary/      Configured supplementary documents
review/attachments/   Attachments referenced by source_attachments.yaml
~~~

Do not rename or omit files listed in `src/offline/config/source_catalog.yaml`, `src/offline/config/source_attachments.yaml`, or `src/offline/review/corrections/`. Verify source versions and hashes when specified in the configuration. If your data is elsewhere, update `data_dir` in `src/offline/config/pipeline.yaml` before running.

### 2. Set Up the Environment and Run the Pipeline

Open PowerShell at the repository root:

~~~powershell
run.bat setup-full
run.bat offline
~~~

`run.bat offline` runs the pipeline configured in `src/offline/config/pipeline.yaml`: source discovery, text extraction/selective OCR, normalization, registry and Article–Clause–Point construction, provenance/versioning, knowledge and graph construction, followed by BM25 and Dense/FAISS indexing. Internet access is required initially to install dependencies and download BGE-M3; runtime depends on corpus size, OCR workload, and hardware.

If your configuration requires local Neo4j, start Docker Desktop first, then run:

~~~powershell
run.bat neo4j
run.bat load-neo4j
~~~

Do not run the Neo4j load command if you are not using local Neo4j or have configured another appropriate destination.

### 3. Validate and Package the Results

~~~powershell
run.bat validate
~~~

When the audit passes, the system creates a timestamped release directory next to the working artifact, usually in the form `releases/YYYYMMDDTHHMMSSffffffZ/`. It contains:

- `vn_labor_online.zip`: the compact package for the ONLINE backend.
- `vn_labor_offline_review.zip`: reports and intermediate data for inspection; do not use it as the backend artifact.
- `release.json`: build ID and SHA-256 hashes for both ZIP files.

Check `reports/final_outputs_validation.json`, `reports/dense_validation.json`, `reports/neo4j_validation.json`, `reports/validation_issues.jsonl`, and `release.json`. If validation does not PASS, inspect each check/detail in the reports, correct the source or configuration, and rerun dependent steps; do not manually change `UNVERIFIED` to `VERIFIED`. A technical PASS does not mean the content has been reviewed by a legal professional.

To run ONLINE locally afterward, copy the correct `vn_labor_online.zip` to `build/releases/` and follow the steps in [Run ONLINE locally](#run-online-locally-on-windows).

## Run the ONLINE Backend on Kaggle

The backend notebook fetches the latest code from `main`, detects artifacts by their structure, checks fingerprints, and stops if they are incompatible. Add only the artifact Dataset; **you do not need to upload the code as a Kaggle Dataset**. Keep the notebook running in an interactive session for the API/tunnel to remain available.

### 1. Import the Correct Notebook

Open [ONLINE_Backend.ipynb on GitHub](https://github.com/tvqui/phap-dien-ai-legalgraphrag/blob/main/src/online/backend/kaggle/ONLINE_Backend.ipynb) and download the `.ipynb` file. In Kaggle, create a new Notebook, select **File → Import Notebook**, and upload the downloaded file. This is the backend notebook, not the OFFLINE or evaluation notebook.

### 2. Add Kaggle Resources

1. Enable **Internet** in Settings.
2. Select GPU **T4 x2** if available.
3. Select **Add Input → Datasets** and add exactly **one** Dataset containing a validated OFFLINE artifact.
4. In Secrets, create and authorize the exact names: `GEMINI_API_KEY`, `VN_LABOR_API_KEY` (a random string of at least 32 characters), and `NGROK_AUTHTOKEN`; `HF_TOKEN` is optional.

To use the prebuilt data in the repository, download `sample_data/vn_labor_online.zip` from GitHub, create a **Private** Kaggle Dataset named `phapdienai-labor-artifact-final-v2`, upload the `vn_labor_online.zip` file, then attach that Dataset via **Add Input**. Do not extract the ZIP or rerun OFFLINE. The backend notebook automatically detects valid ZIP files under `/kaggle/input`; no path needs to be specified if there is only one valid artifact. If you upload an extracted artifact, it is recognized by its `artifacts/` directory containing `00_manifest/`, `01_extracted/`, `02_registry/`, `03_structure/`, `04_knowledge/`, `05_graph/`, `06_indexes/`, and `reports/`.

Do not attach a review package, Gold ZIP, checkpoint, or code bundle in place of the ONLINE artifact.

### 3. Run and Verify

1. Select **Run All** in the interactive session.
2. Wait for the GPU, Input, and Secrets checks, GitHub code retrieval, artifact pinning, and backend startup.
3. The logs should show `Preflight GPU/Internet/Input/Secrets: PASS`, identify the selected Input as the Dataset you added, and display the backend URL.
4. Leave the final cell running. Stopping the cell or closing the session will stop the server/tunnel.

To use the local frontend with the Kaggle backend, put the URL and token in `src/online/frontend/.env` on your local machine:

~~~dotenv
VITE_BACKEND_TARGET=https://URL-BACKEND-VUA-NHAN
BACKEND_PROXY_TOKEN=GIA_TRI_VN_LABOR_API_KEY
~~~

Then run `run.bat frontend` and open http://127.0.0.1:5173. Do not commit `.env`. The tunnel URL may change after Kaggle restarts. When reporting an error, record `Commit in use:`, `Selected Input:`, and the error code; do not share API keys or tokens.

## Build or Resume OFFLINE Data on Kaggle

**Current notebook note:** `VN_Labor_Kaggle_V8.ipynb` uses a checkpoint-first workflow. By default, it resumes AI enrichment from an existing OFFLINE checkpoint; it does not start from an empty Kaggle Input. To build everything from a raw corpus for the first time, run `run.bat offline` locally first or create a separate cold-start notebook. Setting `RESUME_AI_ONLY=False` does not remove the checkpoint requirement.

#### A. Create a Dataset Containing the Code and Corpus

1. First, provide the corpus under `data/` and a valid OFFLINE checkpoint. If starting from a fresh clone, put the corpus and configured review files in the correct locations, then run the local pipeline as described above:
   ~~~powershell
   run.bat setup-full
   run.bat offline
   run.bat validate
   ~~~
   Continue only after validation passes and `artifacts/` contains the required data. This step also creates converted DOCX files from `.doc` sources; the Kaggle packager requires them. If you already have a validated checkpoint, you can reuse it instead of rebuilding.
2. Then create the Kaggle package:
   ~~~powershell
   run.bat kaggle
   ~~~
   The equivalent command is `./.venv/Scripts/python.exe -X utf8 src/offline/scripts/package_kaggle.py`.
3. Check `build/kaggle/package_report.json`. Verify that `zip_crc_check` and `notebook_code_syntax` are `PASS`, and that `corpus_files` is greater than 0. `uploaded: false` and `remote_execution_tested: false` are expected: the script packages files but does not upload them or run them on Kaggle.
4. The ZIP is created at `build/kaggle/vn_labor_kaggle_v8.zip`. Extract it locally; it should contain a `vn_labor_bundle/` directory with `bundle_manifest.json`, `src/offline/kaggle/bootstrap.py`, `src/`, and `data/`.
5. Create a **Private** Kaggle Dataset, for example `vn-labor-code-corpus-v8`. Upload the extracted contents so Kaggle sees this directory tree:
   ~~~text
   vn_labor_bundle/bundle_manifest.json
   vn_labor_bundle/src/offline/kaggle/bootstrap.py
   vn_labor_bundle/data/
   ~~~
   Do not upload only the ZIP inside the Dataset: the notebook must read `bundle_manifest.json` and `src/offline/kaggle/bootstrap.py` directly from the Input. Do not modify files after packaging; the notebook verifies each file's SHA-256.

#### B. Create a Dataset Containing the Checkpoint

The notebook needs exactly one checkpoint in addition to the code/corpus Dataset. Create a **Private** Kaggle Dataset, for example `vn-labor-checkpoint-current`, using one of these sources:

- A complete artifact directory containing `artifacts/00_manifest/files.jsonl`; or
- A checkpoint ZIP exported by an earlier OFFLINE run, usually `vn_labor_results.zip` or `vn_labor_results_recovery.zip`.

If resuming after an interrupted run, prefer the latest `vn_labor_results_recovery.zip`, which may contain the latest AI cache and progress. `vn_labor_results_technical_checkpoint.zip` is created before AI; use it to return to the technical checkpoint before the AI step. Attach only one checkpoint. If multiple are attached, `RESTORE_ARCHIVE="AUTO"` reports multiple sources; do not choose randomly or mix different builds.

#### C. Import the Notebook and Configure Kaggle Inputs

1. In the repository, open `build/submission/offline/VN_Labor_Kaggle_V8.ipynb`. The `package_kaggle.py` step above also generates the equivalent notebook at `build/kaggle/VN_Labor_Kaggle_V8.ipynb` along with the ZIP.
2. Download the notebook. In Kaggle, select Code → New Notebook → File → Import Notebook and upload `VN_Labor_Kaggle_V8.ipynb`.
3. In Settings, enable Internet and select GPU T4 x2. The default AI workflow requires two GPUs: Dense runs on GPU 0 and Ollama `qwen3:8b` on GPU 1. If you do not plan to run AI, change the configuration deliberately; do not bypass the GPU preflight.
4. Under Input → Add Input → Datasets, attach these two Datasets: `vn-labor-code-corpus-v8` and `vn-labor-checkpoint-current`. If you use different names, no code changes are needed; the notebook detects the inputs by their manifests and structure.
5. Under Add-ons → Secrets, create and authorize exactly these four names: `NEO4J_URI`, `NEO4J_USER`, `NEO4J_PASSWORD`, and `NEO4J_DATABASE`. The Aura URI must use the `neo4j+s://...` format; do not put secret values in notebook cells or Datasets.

#### D. Select a Mode and Run

The defaults in the first cell are:

~~~python
RESTORE_ARCHIVE = "AUTO"
RESUME_AI_ONLY = True
REFRESH_EXTRACTION_QUALITY = False
RUN_AI_ENRICHMENT = True
OFFLINE_AI_MODEL = "qwen3:8b"
OFFLINE_AI_MAX_PROVISIONS = 250
LOAD_AURA = True
~~~

Keep these values when resuming AI from a checkpoint. Before calling Ollama, the notebook checks hashes, provenance, and indexes; preserves the AI cache; exports a technical checkpoint; runs any remaining enrichment; loads Aura; audits; and exports the results. Because this is an AI-only resume, it does not OCR the entire corpus or rebuild Dense/BM25.

To refresh extraction from an existing checkpoint, set `REFRESH_EXTRACTION_QUALITY=True` and `RESUME_AI_ONLY=False`; this reruns extraction/selective OCR and takes longer. Do not set `RESUME_AI_ONLY=True` together with `REFRESH_EXTRACTION_QUALITY=True`. This still refreshes from a checkpoint; it is not a clean build from the corpus.

Select **Save Version → Save & Run All** and wait for all cells to finish. Monitor `HEARTBEAT`, the stage, the number of AI items processed, logs, and GPU status. If Kaggle/Ollama fails, preserve the output and use the latest recovery ZIP to resume; do not delete the old checkpoint until you have confirmed the new ZIP can be downloaded.

#### E. Retrieve and Check the Outputs

The notebook displays download links in Output. Download and keep these files separately:

- `vn_labor_online.zip`: this is the only package to use with the Kaggle ONLINE backend. Create a Dataset, for example `phapdienai-labor-artifact-final-v2`, then follow [Run the ONLINE backend on Kaggle](#run-the-online-backend-on-kaggle).
- `vn_labor_offline_review.zip` and `release.json`: review records, intermediate data, build ID, and SHA-256 hashes.
- `vn_labor_results.zip`: completed checkpoint to save or resume work later.
- `vn_labor_results_technical_checkpoint.zip`: technical checkpoint exported before AI.
- `vn_labor_results_recovery.zip`: recovery checkpoint, if one was created after a failure.

In the reports, check `offline_final_run.json`, `tong_hop_sau_chay.md`, `reports/final_outputs_validation.json`, `reports/dense_validation.json`, `reports/neo4j_validation.json`, `reports/validation_issues.jsonl`, and `release.json`. Use `vn_labor_online.zip` only when the audit/validation reports PASS; continue to disclose the actual review status of the legal data and human review.

## Evaluation Notebooks

The main evaluation notebooks are under `evaluation/`: `evaluation/suite/`, `evaluation/notebooks/`, and `evaluation/graph_qa/`. They clone the repository, install the package from that checkout, and save results by run. Recovery notebooks require the original checkpoint and commit; do not change commits when resuming an existing evaluation run.

Before comparing results, verify that the artifact, Gold set, commit, model, and configuration are the same. See the [evaluation README](evaluation/README.md). Do not combine Retrieval, QA, AI-judge, and human review into a single accuracy score.

## Limitations

- The system answers only within the data and legal versions included in the artifact; disclose the snapshot date and approval status.
- A fingerprint confirms that the artifact matches the configuration; it does not prove that the legal sources are correct.
- Do not upload secrets, sensitive data, or private artifacts to a public GitHub repository.
